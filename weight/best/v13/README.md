## 模型

| id | 類別 | id | 類別 | id | 類別 |
| ---: | --- | ---: | --- | ---: | --- |
| 0 | `Oily_Spot` | 3 | `Black_Spot` | 6 | `Thrips` |

## 前處理（兩種格式相同）

1. 依 EXIF 把照片轉正（以手機上顯示的方向為準）
2. **Letterbox 到 640×640**：等比縮放讓長邊等於 640（雙線性），置中，其餘補灰 `(114, 114, 114)`。
   **不要直接拉伸成正方形**，模型是用 letterbox 輸入評估的
3. 通道順序 **RGB**，數值除以 255 → float32，範圍 0–1
4. 排成 **NCHW** `[1, 3, 640, 640]`

> ⚠ **TFLite 的輸入也是 NCHW**，不是 TFLite 常見的 NHWC `[1, 640, 640, 3]`。
> 這個檔案由 PyTorch 直轉（litert-torch），保留了 PyTorch 的維度順序。

## 輸出

形狀 `[1, 300, 6]`，每一列是 `x1, y1, x2, y2, score, class_id`：

- 座標是 **640×640 輸入上的像素座標**。換回原圖：先減掉 letterbox 的左／上補邊，再除以縮放比例
- 已依 `score` 由高到低排好，**不需要再做 NMS**
- `class_id` 是浮點數，轉成整數後對照上表
- 分數門檻建議 **0.25**（ultralytics 推論的預設值）；低於門檻的列直接丟掉

## 為什麼 PyTorch 是 0.861、匯出檔是 0.857

不是轉檔損失。`ultralytics` 用 `.pt` 評估與推論時預設 `rect=True`，
每張圖只補到 32 的倍數（例如 640×480）；匯出檔的輸入尺寸固定，只能補成 640×640 正方形。
補邊多寡不同，少數影像的判斷會改變（例：`Black_Spot_00004.jpg` 在矩形輸入判 Black_Spot 0.83、正方形輸入判 Oily_Spot 0.66）。
**App 端看到的精度以 0.857 為準。**
